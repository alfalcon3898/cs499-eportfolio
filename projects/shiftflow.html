PLANNED SERVICE SCOPE

What I would provide

Restaurant teams coordinating employees, shifts and coverage.

This describes a future offer being developed through this project. Deliverables will be confirmed for each engagement once the relevant capability is demonstrated.

Planned deliverables

  • Employee and shift management with availability and conflict checks.
  • Employee pickup requests with manager review and approval.
  • Manager and employee screens with access appropriate to each role.
  • Database persistence, tests of core workflows and setup documentation.

Handoff & support

The intended handoff includes the agreed source code or configuration, setup instructions, a short demonstration and acceptance checks. Before a project starts, we would agree on required access, delivery milestones, revision limits and a defined support window.

Hosting and third-party API accounts, usage charges and ongoing maintenance would be agreed explicitly.

Possible additions

AI-assisted schedule suggestions, swaps, additional notifications and multi-location support would be separately scoped after the core product works.

Current progress

The current employee lookup API loads stored employee data and handles missing employees and invalid IDs. The latest locally reported top-level test run passed 113 tests.

Planned milestones

  1. Employee and shift workflows
  2. Role and ownership checks
  3. Manager-approved pickup requests and a simple interface

DEMO PLAN / NOT YET PUBLISHED

What the demo will show

Follow a fictional restaurant team through an employee lookup and, as development progresses, a complete shift-coverage workflow.

Example walkthrough

  1. Current API walkthrough: request a saved employee and inspect the returned name, role and target hours.
  2. Compare a successful lookup with an unknown employee ID and a non-integer ID, explaining the 200, 404 and 422 responses.
  3. Planned application walkthrough: create a shift, attempt a conflicting assignment and explain why it is rejected.
  4. Planned approval workflow: an employee requests an open shift, a manager reviews it and the updated schedule is displayed.

How the results will be checked

The recording will pair visible behavior with relevant automated tests. Any schedule screens or approval flows will be labeled planned until implemented.

Demo format

An API walkthrough first, followed by a short screen recording of the working interface when ready. All employee and business data will be fictional.
